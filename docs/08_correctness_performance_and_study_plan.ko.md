## 최적화를 만들기 전에 실패를 만들기

유용한 회귀 픽스처는 화이트보드에서 설명할 수 있을 만큼 작다. 이 실습에서는 같은 시각에 도착해 탈 수 있는 열차, 1초 뒤라서 놓치는 같은 열차, 한 라운드에서 연이어 탈 수 없어야 하는 두 경로, 불편한 순서로 나열된 보행 연결이 여기에 포함된다.

테스트는 자정 넘김, 반복된 정류장 위치, 승차/하차 제한, 추월 거부, 엄격한 접근성 입력 수용, 불변 행, 오래되었거나 일치하지 않는 실시간 정보, 용량 실패, 취소, 잘못된 역방향 처리도 다룬다.

이들은 관측 가능한 의무다. “실패 시 닫힘”이라고 적힌 주석은 실패를 강제하고 성공 결과가 반환되지 않는지 확인하는 테스트를 대신할 수 없다.

## 오라클의 독립성 유지하기

[`oracle.py`](../src/oracle.py)는 우선순위 큐를 사용해 `(stop, exact_boardings)` 상태를 검색한다. 승차 가능한 모든 운행편과 허용된 이후의 모든 하차 위치를 명시적으로 열거한다. 간선을 한 번에 하나씩 걷는다. 프로덕션 스타일 경로 스캔, 마킹된 경로 수집기, 이진 운행편 선택, 범위 엔진 또는 도보 경로 전파 헬퍼를 호출하지 않는다.

두 알고리즘은 같은 문제를 풀어야 하므로 불변 입력 타입과 선언된 보행 정책을 공유한다. 경로 검색 표현이나 가지치기는 공유하지 않는다. 테스트는 첫 번째 목적지 답만이 아니라 모든 승차 예산에 대해 모든 정류장의 도착 시각을 비교한다.

시드가 지정된 무작위 픽스처는 실패의 재현 가능성을 해치지 않으면서 적용 범위를 넓힌다. 범위 동등성은 작은 시간 범위의 모든 정수 초를 사용한다. 역방향 동등성은 완전 열거로 실현 가능한 가장 늦은 순방향 준비 시각을 찾는다.

생성기는 추월하지 않는 운행편을 구성하면서 반복 정류장 패턴, 분기와 짧은 회차, 정차 시간, 불균등한 배차 간격, 승차/하차 마스크를 변화시킨다. 고정된 시드 개수는 입력 다양성의 척도가 아니다. 차등 테스트는 반환된 증거 경로도 `validate_against`를 사용해 원시 입력과 대조해 검증하므로, 올바른 도착 값으로 존재하지 않는 승차나 보행 간선을 숨길 수 없다. 직접 만든 부정 증거 경로는 경로 생성기와 독립적으로 이 검사기를 테스트한다.

이 검사는 제한된 실습 모델에 대한 신뢰를 확립한다. 여러 날짜에 걸친 프로파일 의미론, 실제 출처의 완전성, 완전한 다기준 대표 경로 보존을 입증하지는 않는다.

## 실제로 실행한 것을 측정하기

`ScanMetrics`는 로컬 작업 단위, 라운드, 스캔한 경로, 운행편 조회, 검사한 보행로, 라벨 개선, 유지된 라벨 재사용을 기록한다. 이 구현이 생성한 카운터다.

합성된 `provider_calls=0`, `fallback_calls=0` 또는 “프로덕션 p95” 필드는 없다. 이 실습은 배포된 동작을 관측할 수 없다. 관측할 수 없는 양은 0이 아니다.

벤치마크에서는 입력 컴파일과 첫 번째 쿼리를 기존 인덱스의 반복 쿼리와 구분하라. 보고하는 카운터를 정확한 픽스처와 쿼리에 연결하라. [`Work`](../src/metrics.py)는 로컬 작업 한도, 기한, 취소도 노출한다. 이들은 계산 안에서의 검사이며 배포된 서비스의 측정값이 아니다.

이 실습을 벤치마크한다면 Python 버전, 하드웨어, 픽스처 시드, 정류장/운행편 수, 쿼리 말뭉치, 정확한 명령을 보고하라. 정류장 일곱 개짜리 픽스처의 더 빠른 실행이 프로덕션 서비스 수준 목표를 예측하지는 않는다.

## 실용적인 학습 순서

**1단계: 설명하기.** [00–02장](00_why_transit_needs_raptor.ko.md)을 읽고 `example_routing.py`를 실행하라. 두 목적지 대안이 살아남는 이유와 같은 라운드에서 작성된 라벨로 다른 경로에 승차할 수 없는 이유를 설명하라.

**2단계: 안전하게 깨뜨리기.** 임시 브랜치에서 승차 준비 계산의 `previous`를 `current`로 바꾸거나, 도보 경로 전파를 제거하거나, 추월하는 패턴을 허용하라. 각 버그를 드러내는 가장 작은 회귀 픽스처를 추가하라. 계속하기 전에 올바른 코드를 복원하라.

**3단계: 시간 따라가기.** [03장](03_service_days_and_timetables.ko.md)과 [06장](06_departure_profiles_and_reverse_search.ko.md)을 읽고 노트북 02를 실행하라. `24:xx` 발생 건, 초 단위의 정확한 프로파일 중단점, 여러 출발 시각에 걸쳐 유지되는 행, 가장 늦은 준비 시각과 목적지 도착 기한의 차이를 설명하라.

**4단계: 입력 따라가기.** [04–05장](04_easysubway_end_to_end.ko.md)을 읽어라. 픽스처가 컴파일, 입력 수용 검증, 스캔, 증거 경로 검증을 거치는 과정을 추적하라. 해시처럼 생긴 필드가 서명이 아닌 이유와 시간 순서만으로 승차가 존재함을 입증할 수 없는 이유를 설명하라.

**5단계: 프런티어에 도전하기.** [07장](07_multicriteria_frontiers_and_extensions.ko.md)을 읽고 노트북 03을 실행하라. 하나의 스칼라 중간 라벨 때문에 보행이 가장 적은 후보가 사라지는 사례를 만들어라. 완전한 McRAPTOR를 주장하기 전에 어떤 오라클과 상태 표현이 필요한지 설명하라.

알고리즘 정확성, 입력 수용 검증, 증거 경로 유효성, 측정된 작업량을 서로의 대리 지표로 사용하지 않고 구분할 수 있다면 이 실습의 경계를 이해한 것이다.

## 설정 및 기여 정책

디렉터리 구조는 교육과정의 기준선이지 최대 파일 개수가 아니다. 구조 검사는 필수 학습 자료와 로컬 링크를 보호하면서 새로운 예제, 테스트, 도구를 허용한다. `.github/workflows/ci.yml`은 Python 3.11.14와 3.14.6에서 테스트, 예제, 새 커널 노트북 실행을 수행한다. 어떤 개정판이 CI를 통과했다고 설명하기 전에 실제 GitHub 실행 결과를 확인하라.

기여할 때는 작은 기능 브랜치를 만들고, 실패하는 픽스처를 추가하고, 수정 사항을 구현하고, 영향을 받는 테스트를 실행하라. 노트북 동작이 바뀌면 `python tools/verify_notebooks.py`를 실행하고 `git diff --check`를 확인하라. CI는 전체 스위트를 실행한다. 지원하지 않는 입력이나 알고리즘 영역은 눈에 보이는 경계로 취급해야 하며, 성공한 경로를 지어내라는 초대로 여겨서는 안 된다.
