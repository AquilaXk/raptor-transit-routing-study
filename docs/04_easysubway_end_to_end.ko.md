## 실행 가능한 요청에서 시작하기

저장소 루트에서 `python example_routing.py --ready 08:00:00 --max-transfers 2`를 실행하세요. 이 요청을 설명하는 데 필요한 모든 것은 [예제](../example_routing.py)와 아래의 로컬 모듈에 있습니다. 모든 역 ID, 운행편, 시각, 식별 값은 만들어 낸 것입니다.

요청은 역 밖의 `O`에서 시작해 목적지 밖의 `Z`에서 끝나고, 최대 세 번의 탑승을 허용하며, 계단 없는 보행을 요구합니다. 진입, 환승, 출구 보행은 여정에 포함됩니다. 이 예제의 승차 여유 시간은 60초입니다.

## 입력 구성하고 컴파일하기

[`demo_timetable`](../src/fixtures.py)은 세 가지 패턴을 제공합니다. `A`에서 `X`까지 운행하는 `R1`, `Y`에서 `D`까지 운행하는 `R2`, `A`에서 `D`까지 운행하는 `DIRECT`입니다. 방향성이 있는 보행 간선도 제공합니다.

[`Timetable`, `Route`, `Trip`](../src/timetable.py)은 식별자, 이벤트 시간 순서, 정류장 참조, 호환되는 허용 마스크, 운행편이 추월하지 않는 순서를 검사합니다. 대체 시간표를 추측하는 대신 유효하지 않은 입력을 거부합니다.

[`compile_timetable`](../src/route_index.py)은 정류장 출현 위치, 출발 시각, 보행 인덱스를 만듭니다. 같은 정류장을 반복해서 방문하면 각 위치를 별도로 유지합니다. 컴파일은 제공된 시간표를 검색할 수 있게 만들지만, 만들어 낸 데이터가 공식 출처에서 왔다는 사실을 입증하지는 않습니다.

## 스캔 전에 질의 수용 여부 검증하기

[`raptor`](../src/raptor.py)는 정류장 ID, 준비 시각, 탑승 횟수 상한, 여유 시간을 검증합니다. [`WalkPolicy.admit`](../src/accessibility.py)은 보행 정책에 필요한 근거를 검사합니다. 엄격 모드에서는 계단으로 알려진 간선을 제외하고, 알 수 없거나 검증되지 않은 근거가 있으면 스냅샷을 거부합니다.

[`Work` 객체](../src/metrics.py)는 작업량 한도, 마감 시각, 취소를 검사합니다. 이런 실패는 주어진 제약 안에서 계산을 완료할 수 없었다는 뜻입니다. 경로가 없는 성공적인 탐색으로 보고해서는 안 됩니다.

## 유용한 두 탑승 횟수 예산 추적하기

0번째 라운드는 `O`에서 08:00에 준비된 상태로 시작합니다. [보행 폐쇄](../src/footpaths.py)는 60초가 걸리는 ENTRY 간선을 따라 `A`로 이동해 08:01에 승강장에서 준비된 상태를 만듭니다.

1번째 라운드에서 [스캔](../src/route_scan.py)은 탑승할 때 0번째 라운드의 라벨만 읽습니다. 승차 여유 시간이 60초이면 08:02 `R1` 출발편을 정확히 같은 시각에 탈 수 있습니다. 이 운행편은 `X`에 08:10에 도착합니다. 같은 탑승 횟수 예산으로 08:04에 `DIRECT`를 타고 `D`에 08:29에 도착한 뒤, EXIT를 완료해 `Z`에 08:30에 도착할 수 있습니다.

`X`에서 `Y`로 엄격하게 환승하는 데 120초가 걸립니다. 따라서 `Y`에서 08:12에 준비되고, 승차 여유 시간 60초를 더하면 2번째 라운드에서 08:13 `R2` 출발편을 탈 수 있습니다. `D`에는 08:21에 도착하고 EXIT를 마치면 08:22입니다.

| 탑승 횟수 예산 | 목적지 도착 | 유지하는 이유 |
|---|---|---|
| 한 번 | 08:30 | 환승 없음 |
| 두 번 | 08:22 | 한 번 환승하고 더 일찍 도착 |

도착 시각과 탑승 횟수 기준에서 어느 선택도 다른 선택을 지배하지 않습니다. 화면 표시 선호 때문에 탐색 안에서 이 차이를 지워서는 안 됩니다.

## 결과 추출하고 경로 증거 검사하기

[`SearchResult.journeys`](../src/round_state.py)는 불변 행에서 도착 시각/탑승 횟수 기준으로 지배되지 않는 대안을 추출합니다. 각 여정은 도착 시각을 설명하는 보행 및 탑승 구간을 가집니다.

명령줄 예제는 내부 시간 순서를 검사하는 [`Journey.validate`](../src/journey.py)를 호출합니다. 더 강하게 검사하려면 `validate_against`를 사용해 실제 입력과 경로 증거를 대조하세요. 운행편 식별 정보, 순서가 정해진 정류장 위치, 승차/하차 허용 여부, 이벤트 시각, 방향성이 있는 보행 간선, 정책에 따라 조정된 보행 시간을 검사합니다.

다음 코드는 저장소 루트에서 실행할 수 있습니다.

```python
from src import compile_timetable, demo_timetable, raptor, parse_time, WalkPolicy

timetable = demo_timetable()
policy = WalkPolicy(strict_step_free=True)
result = raptor(
    compile_timetable(timetable), "O", "Z", parse_time("08:00:00"),
    max_boardings=3, boarding_slack=60, policy=policy,
)
for journey in result.journeys():
    journey.validate_against(timetable, boarding_slack=60, policy=policy)
```

[경로 증거 테스트](../tests/test_witness.py)는 시간 순서만으로는 감지할 수 없는 방식으로 경로를 의도적으로 손상시킵니다. 유효한 경로 증거는 제공된 입력 아래에서 실행 가능하다는 사실을 입증합니다. 최적성은 [오라클 비교](../tests/test_oracle.py)를 사용해 별도로 검사합니다.

## 입력 이야기를 바꾸지 않고 관련 계산 따라가기

| 질문 | 로컬 진입점 | 범위 |
|---|---|---|
| 준비 시간 구간에서 무엇이 바뀌는가? | [`rraptor`](../src/profile.py) | 운행일 하나, 고정 보행, 도착 시각/탑승 횟수 목적, 대중교통 탑승이 필요한 출발지와 목적지 |
| 마감 시각에 맞추려면 언제 출발할 수 있는가? | [`arrive_by`](../src/reverse.py) | 제공된 시간표를 대상으로 한 자체 역방향 스캔 |
| 마지막으로 가능한 연결편은 무엇인가? | [`last_connection`](../src/reverse.py) | 제공된 운행일의 이벤트 범위, 대중교통 탑승이 필요한 출발지와 목적지 |
| 지연은 입력에 어떤 영향을 주는가? | [`apply_snapshot`](../src/realtime.py) | 검증된 번들/날짜 식별 정보, 운행편 전체에 적용하는 음수가 아닌 지연과 취소 |
| 어떤 목적 벡터가 살아남는가? | [`bounded_frontier`](../src/pareto.py) | 다기준 노선 스캔이 아닌 별도의 지배 관계 연습 |

수용 검증을 통과한 Point 탐색에서 실행 가능한 여정이 없으면 빈 결과를 반환합니다. 유효하지 않은 입력, 사용할 수 없는 근거, 지원되지 않는 프로파일 영역, 초과한 한도는 타입이 지정된 오류를 발생시킵니다. 어느 결과도 이전에 성공한 경로를 가져오지 않습니다.

## 이 구현의 범위 밖에는 무엇이 있는가?

이 실습은 여러 운행일을 로드하거나 병합하지 않고, 배차 간격에서 정확한 출발편을 추론하지 않으며, 서명된 데이터를 검증하지 않고, 완전한 다기준 상태를 노선 스캔에 통합하지 않습니다. [03장](03_service_days_and_timetables.ko.md), [06장](06_departure_profiles_and_reverse_search.ko.md), [07장](07_multicriteria_frontiers_and_extensions.ko.md)은 부족한 입력과 상태 요구사항을 설명합니다.

네트워크 API, 실시간 데이터 제공자, 승객용 UI, 배포 시스템은 없습니다. 여기에서 설명한 동작의 근거는 Python 예제와 테스트입니다.

## 연습문제와 답

준비 시각을 08:00:00에서 08:00:01로 옮겨 보세요. 이제 ENTRY와 승차 여유 시간을 더하면 08:02:01이 되어 첫 `R1`을 놓칩니다. 다음 `R1`은 `X`에 08:15에 도착합니다. 환승 시간과 여유 시간을 더하면 08:18 `R2`를 탈 수 있고, EXIT를 완료하면 08:27입니다. 08:30 직행 여정도 여전히 가능합니다.

이 1초의 변화는 라운드 스캔을 06장에서 배우는 정확한 이벤트 경계와 연결합니다.
